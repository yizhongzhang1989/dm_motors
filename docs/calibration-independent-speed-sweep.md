# 独立轴高速滑动摩擦实验

协议名：`independent_speed_sweep_v1`。本流程用于 A（id=1）、C（id=3）物理分离后，分别测量稳速运行所需的报告力矩，确认两方向实际速度至少达到 `4π rad/s`（约 12.5664 rad/s、120 rpm），并比较原有窄速度域模型在高速下的预测误差。

这是独立的高速滑动实验类型 `speed_sweep`。它不修改原有 quick、low_speed 或 precision 协议，不估计惯量 J、静摩擦、绝对力矩标尺，也不自动生成 `calibration.json` 或改写 `config/system_parameters.yaml`。候选通过表示在这些独立验证轮上预测达标；重新联轴后的补偿效果需要另行测试。

## 1. 为什么需要独立轴流程

联轴时 C 的驱动力矩包含 C 自身损耗和 A 的需求，无法仅由两轴总和唯一分解 A/C 摩擦。此前 A 的合格模型速度范围约为 ±0.4 rad/s，不能据此判断 13 rad/s 下黏性损耗为零。

现有短行程 low_speed 报告使用所有速度共用的 ±0.03 rad 区间。在 13.2 rad/s 下穿越此区间仅约 4.55 ms，500 Hz 采样不足以做其规定的20点分析。precision 则要求完整转数、多次重复、静摩擦与恰为 2π 的最高档，不能仅改一个速度参数便当作本协议。独立高速流程因此使用自己的短平台、训练/验证划分与报告。

## 2. 实验计划与实际速度

每轴的正式计划在采集前固定：

| 用途 | 速度幅值 / rad/s | 每档双向轮数 |
| --- | --- | --- |
| 训练 | 0.6、3、9、13.2 | 2 |
| 整轮独立验证 | 1.5、6、13.2 | 1 |

共11个独立双向轮次、22个方向窗口。13.2 rad/s 的验证轮与同档训练轮是独立采集，不能复制训练数据代替。训练两次重复提供范围对照，不作为高置信度精密重复性认证。

原生目标流每2 ms发布一次。每个方向采用平滑升速、0.6秒恒速平台、平滑降速；平台前后各裁去0.15秒，使用事先确定的中央0.3秒。斜坡时长 `max(0.25, speed/15)`，单腿位移为 `speed × (ramp + 0.6)`，最高档约19.536 rad。单个双向最高档轮次的目标轨迹约5.77秒，准备与停止确认另计。

位置命令仍必须落在原生可编码范围内。不能直接从任意当前角度启动最高档：运行器根据实际起点和首运动方向核验完整轨迹；必要时先独立预定位，不能通过改软件零位隐去越界。每次仅使能被测轴，其他轴保持失能；双边控制保持停止。轴是否仍机械相连也会影响被动轴位移检查。

“达到4π”以规定窗口内的实测位置对源时间的 OLS 斜率为准。它不是目标速度、单包速度反馈峰值或一方向的结果。最高速度的每一个规定方向/轮次都必须通过，窗口还检查反馈间隙、指令证据、方向、速度误差与完整性。未通过的轮次保留在报告中。

## 3. 必须记录的配置

每轴保留电机身份：namespace、id、型号/量化范围、MIT模式、方向、软件偏置、仿真标记，以及采集时配置和源文件指纹。拓扑记录为物理分离；重新联轴后另建实验，不覆盖此次结果。

运行器只读确认实际 RAM `V_BW`。A/C 带宽不同会影响加减速与报告链表现，不能把这种差别直接解释为摩擦差别。记录实际带宽和温度，跨轴/跨批比较时明确是否一致。

原始记录包括目标、feedback、state、总线/CAN记录、起停事件、原生流摘要和独立监控结果。`TRIAL_RESULT.json` 的 `success`、`stop_confirmed`、规定角色和重复编号共同进入分析。收到停止请求的服务回包不等同实际失能确认。

## 4. 离线模型和含义

仅使用通过质量检查的训练窗口，以每个方向窗口等权拟合：

```text
reported_torque = coulomb × sign(measured_speed)
                + viscous × measured_speed
                + bias
```

`coulomb` 与 `viscous` 约束为非负；`bias` 可正可负。候选类型是 `sliding_friction / coulomb_viscous_bias`，没有惯量字段。中央平台的时间加权报告力矩是拟合目标；同时保留角度加权均值、角度范围等作为诊断，不用后者自动修正前者。

所有模型参数由训练轮确定。验证轮只计算冻结模型的误差，不能因验证失败重新选窗或丢弃困难速度。版本1的验证 RMS 门限为0.03 Nm、单窗最大误差门限为0.06 Nm，其他门限以报告中的 `settings` 为准。记录中的 `prediction_qualified` 与 `acquisition_quality_passed` 分开；部署资格 `qualified` 始终为 `false`。

物理限制：

- 报告力矩来自固件电流换算，没有独立轴上力矩传感器，统计误差小不等于绝对力矩标尺准确。
- 0.3秒窗口不是整圈平均；即使最高档也仅约0.63圈，位置相关损耗可能残留。
- `bias` 可以包含方向不对称或恒定负载，不能当作已测传感器零偏；生产摩擦补偿也不能直接套入该偏置。
- 速度包络描述测得的端点范围，不证明每个中间速度、位置与温度均已独立验证；零速附近的模型图留空。
- 稳速窗口不能重新辨识 J；功率项是报告力矩乘轴运动的代理值，不是电功率或效率测量。

旧模型对照必须列出其原始有效速度域。高速误差属于域外外推表现，不能据此否定它当初在低速范围的资格。新候选更能预测高速滑动力矩，也不自动代表联轴补偿已优于旧参数。

## 5. 离线分析、导入与恢复

下面命令只读原始实验并创建新输出，不连接电机。`identity.json` 使用采集时实际身份；`trial-*` 应显式列出同一轴同一批次的规定轮次，避免混入预试或另一轴。

```bash
PYTHONPATH="$PWD/src/dm_motor_calibration" python3 -m dm_motor_calibration.cli speed-sweep-analyze \
  /absolute/path/trial-01 /absolute/path/trial-02 \
  --identity /absolute/path/identity.json \
  --old-calibration /absolute/path/old-calibration.json \
  --output /absolute/path/new-analysis
```

上述两个输入仅演示命令形式；正式资格要求全部11轮。C没有旧独立模型时省略 `--old-calibration`。分析器将原始试次必要文件复制到输出的 `raw/`，记录相对路径、SHA-256与字节数；之后可以独立搬移整个目录。

准备或启动阶段的失败诊断需要另外显式传入，可重复使用 `--diagnostic-trial /absolute/path/attempt`。分析器核对原始来源、目标与全轴停止证据，只允许排除尚未进入正式速度轨迹的尝试；已经发送运动目标的失败不能通过此选项隐藏。诊断可包含 ENABLE 请求，或仅含起点 `baseline` 保持目标，例如8条零速原位目标。报告以折叠明细保留请求、条数、原因和停止确认，不把曾请求使能的记录写成“未使能”，也不计作正式运动失败或拟合样本。

输出包括：

| 文件 | 内容 |
| --- | --- |
| `report.json` | 实验身份、终态、停止确认、候选、全部分析与输入清单 |
| `analysis.json` | `speed_sweep` 分析对象，必须与主报告一致 |
| `samples.csv` | 全程展示与追溯样本，保留源时间、试次编号与训练/验证标记 |
| `plot_data.json` | 图形数据；不取代原始记录或质量计算 |
| `REPORT.md` | 便于阅读的离线结果 |
| `raw/`、`analysis_source.py` | 原始试次、分析版本与复现证据 |

生成可分享的单文件HTML：

```bash
PYTHONPATH="$PWD/src/dm_motor_calibration" python3 -m dm_motor_calibration.cli report \
  /absolute/path/new-analysis
```

生成的 `analysis.html` 内嵌图表和样式，只读且无需ROS。展示训练与独立验证点、候选曲线、所有失败窗口、旧模型对照、范围、实际4π门槛和完整数值。各独立轮次的运动分开绘制，避免把失能间隔画成连续运动。

现有dashboard只索引 `YYYYMMDDTHHMMSS-xxxxxxxx` 格式的实验目录。可以直接让分析器输出到符合该格式的新目录，或用离线导入创建历史记录：

```bash
PYTHONPATH="$PWD/src/dm_motor_calibration" python3 -m dm_motor_calibration.cli import-experiment \
  /absolute/path/new-analysis \
  --history-root /absolute/path/dashboard-output-directory
```

导入先核对主报告、分析、样本和源记录哈希；创建全新目录，复制输入，并保存原报告与导入来源。它不会重新标定、重新赋予资格或改写原目录。导入后的实验在对应轴dashboard中按最新记录恢复，保留现有总体布局：过程曲线、候选参数、验证概要、折叠的逐段明细和报告下载。历史候选不进入“测试并保存生产模型”的选择链。

本台架的 A 报告面板使用8087端口，C报告面板使用8089端口；Motor 3 的实时原始状态面板是8088。C的8089只需启动dashboard并指定 `/motor_3` 与报告目录，无需启动标定collector，控制器未连接时仍可恢复历史。A现有collector会以状态中的 `output_directory` 覆盖dashboard启动值，因此两轴最终报告都归入 `/home/robot/.ros/dm_motor_calibration`。新版观察器统一使用 `ROS_LOCALHOST_ONLY=0` 与项目的 `fastdds_loopback_udp.xml`；Python模块与web资源均从同一新安装overlay加载。

若修改了任一受清单保护的原始文件，恢复/导入会报错，不能继续把它显示为已核验记录。哈希一致只证明保存字节一致，不能证明总线或DDS从未丢帧。

## 6. 重新联轴后的下一轮

保留两轴独立的候选、实际带宽、温度和速度覆盖，随后由新的机械拓扑实验确认方向关系与连接一致性。在相同速度计划下，比较 C 的驱动力矩、A 的实际输出、双向和单向模式之间的差值，并检查高速跟随、换向、松手和启停。

独立轴记录回答“每轴稳速报告损耗如何随速度变化”；联轴记录才回答“把候选用于补偿后，双边拖动是否接近单边轻松”。两类证据互相补充，不能互相替代。
