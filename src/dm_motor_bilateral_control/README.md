# 标准双边力控

独立的相对坐标 MIT PD 双边耦合控制器，默认使用共享参考，支持两轴摩擦补偿及 Dashboard。
算法参考 `DM_Motors_ref/dev/bilateral_control`，不是简易版绝对位置/速度互换。
控制器只使用生产电机 Topic，不读取仿真真值或外力接口。
控制器启动、打开页面和重连均不自动使能；控制器不自动清错、切模式、设零或写 Flash。
双边 bringup 中的驱动在失能初始化阶段配置 MIT 模式及下述 RAM 速度带宽。

从原理到另一台机器的部署与验收，参见[高刚度、低拖动阻力双边力控教程](../../docs/bilateral-control-tutorial.md)。教程区分2026-11-04已验收的`differential_torque`历史版本与11-05共同时间弹簧、显式B轴速度助力的台架实测方案；本包通用默认仍为`shared_reference`。

## Quickstart

先加载 ROS 和工作空间环境。先用物理仿真，不与相同 namespace 的其它 bringup 同时启动：

```bash
ros2 launch dm_motor_bringup bilateral_control.launch.py simulation:=true
```

双边面板默认 <http://127.0.0.1:8084/>，两台电机面板为 8081/8082，CAN 为 8080。
面板默认监听 `0.0.0.0`，仅用于可信内网；省略端口参数自动使用所选配置。
每个 launch 均可传 `config_file:=/绝对路径/site.yaml`，不传则读取默认配置。
如需无网页，显式传 `can_dashboard_ports:='{}' motor_dashboard_ports:='{}' dashboard_port:="''"`，
或在配置中将端口映射设为 `{}`、单端口设为 `''`。
明确点击右上「开始」才使能，点击「停止」后等待两台新鲜反馈确认失能。
用电机面板的外力圆盘或锚点施加扰动，观察双向力矩与位移。

真机使用双边 bringup 选择匹配的驱动初始化配置，启动后仍保持失能：

```bash
ros2 launch dm_motor_bringup bilateral_control.launch.py
```

已有两台电机驱动，且其频率、保护和实际速度带宽均满足要求时，可只附加控制器与面板：

```bash
ros2 launch dm_motor_bilateral_control bilateral_control.launch.py
```

该附加入口不选择电机后端，也不设置现有电机的速度带宽。只有面板时使用包内 `dashboard.launch.py`。
默认真机 bringup 不带 `simulation:=true`，须先确认现场条件，不能直接用于无人值守实物试动。
不要同时启动主从和双边运动，两者都允许非独占输入，最后有效目标生效。

## 默认共享参考模式

启动参数 `control_mode` 默认是 `shared_reference`，旧 `native` 模式仍可显式选择；运行中不可切换。
面板中的 Kc/Dc 始终表示两轴之间的有效耦合系数。共享参考将其映射为电机 MIT
`Kp=2Kc`、`Kd=2Dc+B`：默认 Kc=50、Dc=0.4975、B=0.005，对应实际请求 Kp=100、Kd=1。
能力检查、力矩预算与编码修正均使用映射后的原生 MIT 增益，不能把有效 Kc=50 当作原生 Kp=50。

共享位置参考取两轴最新相对位置的平均值，会随两轴运动，不固定在启动时的世界坐标。共同速度取各轴最新速度经 8 ms 滤波后的平均值，滤波按各自采集时间推进；不做位置预测。虚拟角差分配为两侧各半，误差定义仍为 `e_virtual=e_raw+offset`。失联、停机和重新启动均复位滤波；偏置到期仍先确认双轴停机，再清除偏置。

用 `xA=qA-qA0`、`xB=d*(qB-qB0)` 表示方向映射后的相对位置，`c=(xA+xB)/2`。
无角差注入时，位置目标是 `q_desA=qA0+c`、`q_desB=qB0+d*c`；
速度目标取共同滤后速度，比例为 `2Dc/(2Dc+B)`。分母为 0 时速度目标与 Kd 均为 0。

当前驱动请求策略为 Kp≤500、Kd≤1，共享模式要求 `0≤Kc≤250`、`2Dc+B≤1`，
并继续受两台驱动更小的能力限制：`2Kc≤min(kp_limit)`、`2Dc+B≤min(kd_limit)`。
协议本身可编码 Kd 到 5；本项目保留较小的请求上限，放宽它不能替代稳定性验证。
共同参考的采样与传输延迟仍会产生推动阻力，不能把很小的 B 等同于无惯量或无阻力。

正式默认参数如下，具体实例仍以统一配置及面板中已应用的值为准：

| 参数 | 默认值 |
| --- | ---: |
| `control_mode` | `shared_reference` |
| `coupling_mode` | `bilateral`，双向耦合 |
| 有效耦合刚度 `Kc` | 50 Nm/rad |
| 有效耦合阻尼 `Dc` | 0.4975 Nm/(rad/s) |
| 本地阻尼 `B` | 0.005 Nm/(rad/s) |
| 映射后的原生 MIT Kp / Kd | 100 / 1 |
| 控制器与双边驱动频率 | 500 Hz |
| `required_velocity_bandwidth` | 100 Hz |
| 应用预算 `max_torque` | 0，不额外限矩 |
| 模型摩擦比例 `friction_compensation_fraction` | 0.6 |
| 每轴模型摩擦上限 `friction_torque_limit` | 0.2 Nm |

启动参数 `rate` 支持 20～1000 Hz；默认仍为 500 Hz。两台驱动的实际 `control_rate`
均须覆盖控制器频率，开始前会分别核对。人工测试入口只接受已纳入对照流程的 500/1000 Hz，
并继续要求每次开始独立核验 V_BW=100；允许配置 1000 Hz 不等于已通过现场手感验收。

当前控制结构、模型限制与部署验收见[双边力控教程](../../docs/bilateral-control-tutorial.md)。

## 差模力矩模式及真机试验

显式选择 `control_mode=differential_torque` 时，主机对相对误差计算
`C_A=-Kc*(xA-xB+offset)`、`C_B=-d*C_A`，通过 MIT 前馈发送；原生 `Kp=0`、`Kd=2Dc+B`。
共同速度参考及8ms滤波沿用共享模式。两轴连续弹簧力在共同方向抵消，消除了共同位置参考延迟引入的阻力；编码量化仍会留下小残差。

该模式默认只允许两台模拟电机，节点在获取会话前检查，Dashboard也拒绝未明确开放的真机开始请求。
独立真机试验可在启动时显式设置只读参数`allow_differential_hardware=true`；它只允许差模模式，不能运行中开启，也不允许模拟与真机混用。

2026-11-04 的历史差模版本完成±5°、±30°自动角差检查及持续手动拖动；它当时直接相减两轴latest位置。
操作者确认阻力相比之前显著减小，主动快速拖动时没有异常振动；最后触发10rad/s手测速度保护并确认双轴停机。
参数、原始失败记录、停机证据及结论范围见[差模真机测试报告](docs/2026-11-04-differential-hardware.md)。
Dashboard从新鲜参数读回核对该许可，并显示“真机试验模式”。该许可不改变原有反馈、故障、会话或停机检查，也不等同于已经通过现场手感验收。
有效Kc可设0～500，但通过程序范围检查不等于任意刚度/延迟组合都经过稳定性验证。
推荐参数和实际验证范围见[仿真配置](../../config/bilateral_optimized_simulation_20261104.md)及[实验报告](docs/2026-11-04-differential-simulation.md)。

零应用预算时保留完整原生Kd，弹簧共同缩放只用于满足前馈字段的协议余量；大角差不再通过未使用的位置字段导致命令被拒绝。
正应用预算仍会共同缩小弹簧和原生阻尼以满足预算。`friction_torque`只报告摩擦补偿，实际前馈目标另含弹簧、扰动和编码修正。
`gain_scale`表示原生增益/恢复比例，不能由它推断弹簧是否受协议限制；应同时查看饱和标记。
未加入位置预测或加速前馈；这两类候选的失败结果保存在实验报告中。
角差自动报告按控制模式判定：旧模式保留逐轴最小位移要求，差模使用相对位移的方向、闭合、过冲和停稳，并保留每轴及相对运动的振动检测。
共同坐标自由时，摩擦较小的一轴可能承担大部分位移，因此不要求差模两轴各转偏置的一半。

### 2026-11-05：共同时间弹簧与B轴速度助力

高速共同运动中，异步latest位置相减会把反馈到达错相变成伪相对角差。当前差模节点改为从已收到的
连续关节位置历史中，优先在两轴最新采集时间的较小值处作线性插值，只将这两个位置用于弹簧。
若该处落在过宽间隔内，则向前寻找最近的合法共同历史时间，仍对每个参与端点和插值跨度执行相同检查。
不外推、不使用仿真真值；共同速度参考、原生本地D及摩擦速度输入保持原路径。
所有插值端点受`feedback_age`约束，当前源码的插值跨度不超过`min(feedback_age, 4/rate)`，500 Hz时为8 ms。
缺少有效历史时不能使能；活动耦合中同步输入无效则请求双停，不回退到异步latest。
核心可选参数省略时保留的旧计算仅用于离线基线/中性验证，不能作为实际运行的失效回退。

此前5 ms边界候选的真实节点配合脚本反馈，在13.2 rad/s、A延迟8 ms用例中将检查窗口的伪力矩峰值从约5.30降至0.0244 Nm；
闭环物理仿真的10 ms单轴交付停顿对照中，B报告速度峰值从15.617降至13.663 rad/s。
这些分别验证接线与特定模型中的机制。5 ms版真机`v7-sync-06-on`通过，`v7-sync-9-on`在约5.01177 ms
插值跨度超过5 ms边界时STOP。根据历史最大6.652 ms的三周期批次，当前源码将边界调整为8 ms，
仍保留20 ms端点年龄、无外推及异常停机；8 ms版本的0.6、9、13.2 rad/s开启原补偿短轮已通过。
13.2轮两轴双向实测约13.18 rad/s。B80速度助力的早期四速度短轮与3 rad/s释放记录保留；高速释放V13曾因8.121 ms接收跨度停止。
当前合法共同历史搜索修复保留8 ms跨度、20 ms端点年龄，已通过后续高速往返与释放。所选B100仅把B附加粘性系数设为独立辨识的0.02584737521699079 Nm·s/rad，A附加项为0，原摩擦模型仍按0.6比例计算。

及[三电机阶段报告](../../docs/experiment-history.md#three-motor-bilateral-baseline-2026-11-05)。

Dashboard的`position_error`/`virtual_position_error`仍来自健康历史pair，尚未表示实际共同时间弹簧输入。

<a id="unilateral-coupling"></a>
### 单向跟随对照：A带动B

`coupling_mode`默认`bilateral`。显式选择`a_leads_b`后，A不接收来自B的弹簧和速度反作用，B继续使用原双边算法跟随A。
该模式仅支持`control_mode=differential_torque`且`max_torque=0`，避免共同力矩预算重新引入B对A的影响；其他组合和未知值会被拒绝。
它保留两轴原生`Kp=0`、`Kd=2Dc+B`、按采集时间推进的速度滤波、编码修正、共同时间位置检查及两轴各自的摩擦/附加粘性补偿。
A的弹簧项为0，速度参考改为`2Dc/(2Dc+B)*filtered_vA`（分母为0时取0）；B的目标计算不变。
因此A仍有本地阻尼与自身滤波的动态作用，不能把“没有B反作用”解释为零阻力或零惯量。

只有控制器停止、两轴均取得新鲜失能反馈时才能切换；运行中修改会被拒绝。对已经以差模启动且满足上述条件的实例：

```bash
ros2 param set /bilateral_control coupling_mode a_leads_b
ros2 param get /bilateral_control coupling_mode
```

设置参数不会使能。下一次仍需显式START并完成原核验；ACTIVE消息包含`Unilateral A leads B, no B reaction on A`。
STOP确认后可将参数设回`bilateral`。三轴台架由C拖动A、B单向跟随；使用[台架对比工具](../../tools/physical_rig/bilateral/README.md#coupling-comparison)可按轮设置并恢复模式与补偿开关。

2026-11-05的V16长测及原B100四场验收均属于`bilateral`历史结果，不能沿用为单向模式的验收。
2026-11-06的[单向仿真记录](/home/robot/.ros/dm_motor_bilateral_control/coupling-comparison-20261106/virtual-unilateral/RESULTS.json)中，健康13.2 rad/s拖动和最坏批次轻触通过原门；拆除C的最坏释放速度增长10.173%，超过10%门限。
单向模式尚未通过完整释放验证。2026-11-06真机四档速度的16轮U/D对比已全部完成：双向减单向的C平均力矩差依次为+0.0276、+0.0140、−0.0193、−0.0629 Nm；双向的去趋势力矩纹波仍较大，不能宣称手感完全一致。完整方法、图表、实际速度与限制见[三轴对比报告](../../docs/experiment-history.md#2026-11-06-bilateral-unilateral-comparison)。这16轮始终由C位置伺服驱动，不构成拆除C的释放验收。

## 速度带宽初始化与每次开始核验

驱动的全局 `startup_velocity_bandwidth` 默认是 0，表示不更改速度带宽；
只有 `dm_motor_bringup/bilateral_control.launch.py` 的双边 profile 将其设为 **100 Hz**。
驱动在失能初始化阶段先读取电机 `V_BW`，必要时设置 RAM 值并独立读回，确认后才就绪。
该过程不使能、不保存 Flash，也不修改编码器零点。

控制器的只读启动参数 `required_velocity_bandwidth=100` 是另一项独立要求。
**每次 START** 都重新读取两轴 `V_BW`，等待各自操作结果确认，并要求两轴均取得读回之后的新鲜失能反馈，
还要等待维护窗口退出、双方活动可用，才继续双边使能。
实际读回必须等于所要求值的 float32 表示；排队成功或旧的读回缓存不算通过。
带宽不符、读回超时或反馈失鲜会拒绝开始，控制器不会在 START 中自动写寄存器、修正带宽或清故障。
显式设为 0 可关闭这项核验，主要用于保留旧模式回归；它不证明当前实物带宽适合所选控制参数。

面板只读显示“速度带宽 100 Hz · 开始前核验”或本次“已核验”，没有带宽写入旋钮。
STOP 清除本次核验标志及读回显示，但**保留电机 RAM 的 100 Hz**，不恢复旧 40 Hz。
其他入口的 `startup_velocity_bandwidth=0` 不访问该参数，也不会把已有的 100 Hz 恢复为 40 Hz。
电源复位可能重新加载 Flash 中原先保存的值；应保持失能，按正确双边 profile 重启驱动，
等待初始化及读回完成后再显式开始。只刷新网页或重新附加控制器不会设置电机带宽；
反复 START 也不会自动修复不匹配。无需为正常使用保存 Flash。

## 旧模式 native

以下对端参考公式仅属于显式选择的 `native` 兼容模式，不是当前默认共享参考公式。
启动时同样记录原点 `qA0/qB0`，方向 `d=±1`：

```text
q_desA = qA0 + d*(qB-qB0)
q_desB = qB0 + d*(qA-qA0)
Kp = Kc, Kd = Dc+B
v_desA = d*Dc/(Dc+B)*filtered_vB
v_desB = d*Dc/(Dc+B)*filtered_vA
tau_ffA = friction_A(feedback_vA) + encoding_correction_A
tau_ffB = friction_B(feedback_vB) + encoding_correction_B
```

`Dc+B=0` 时速度目标和 Kd 均为 0。Dc 抑制两轴的相对运动，B 增加每轴的本地拖动阻尼；
两端按方向映射后同速运动时 Dc 项相互抵消，B 项仍产生阻力。增益及补偿默认值集中在统一配置中，
以运行面板的已应用参数为准；允许显式设置 `B=0`，但这不等于无摩擦或无惯量。
这是两端相对弹簧/阻尼，不是外力传感器闭环，也没有自动共同位置保持。
安装偏置不会导致开始时主动靠拢；方向反转和软件零偏均通过生产驱动坐标转换。

对端速度前馈经过 8 ms 一阶滤波，只在采集时间推进时更新；重复时间戳不重复推进。
电机内部 MIT 环仍使用自身反馈及完整的 `Kd=Dc+B`，不会把该滤波加到本侧阻尼回路。
这使高频跨轴速度反馈衰减，保留低频的 Dc/B 配比；代价是共同加速时增加动态阻力，
并不等于零惯量。开始、停止和反馈降级清零时一起重置滤波状态。

对端位置来自选中的反馈配对，用同一个滤后速度作有限的时间对齐：
`q_peer_aligned = q_peer + filtered_v_peer * clamp(t_local_latest - t_peer_pair, -0.002, 0.002)`。
真实采集时间差仍须位于 `feedback_age` 内，预测最多向前或向后 2 ms；
增大新鲜期限不会增大预测增益。该计算不改写反馈或采集时间戳，不使用仿真真值。
零预算模式下，控制计算使用 12 位速度反馈所在量化区间的中点估计，
以减小解码下边缘带来的方向偏差；原始反馈、记录及保护检查保持原值。
native 的正预算模式保留原反馈速度计算；共享参考在两种预算下都采用速度区间中点估计。

## 共用力矩预算与保护

每个周期使用生产 MIT 编解码器估算量化后的 PD＋总前馈力矩，支持两种应用预算模式：

- `max_torque=0`：不额外施加应用层总力矩预算。正常通信时保持设定的 Kp/Kd，
  不随角差增大而降低刚度或阻尼；反馈降级和恢复时仍按既有进度清零、爬升。
- `max_torque>0`：保留共同预算行为。先扣除每轴解码前馈的绝对值，
  再用双方共同的比例缩小 Kp/Kd，使量化总估算位于预算内；不独立裁剪两侧位置目标。

两种模式下，摩擦前馈均随反馈恢复进度渐进恢复。
仅在零预算模式下，用已知的位置/速度指令编码残差计算独立前馈修正，
减轻小 B 时速度目标再次向下量化产生的额外阻力。修正只使用前馈字段剩余空间，
不改变固定 Kp/Kd，不改写目标采集数据，也不是惯量、外力或设备实际饱和补偿。
因此关闭摩擦模型后仍可能存在小额编码修正；摩擦分量、编码修正和总前馈请求在面板中分开显示。
MIT 对称力矩码没有精确零；0 请求约解码为 `-TMAX/4095`，不会伪造零偏补偿。
估算使用最新反馈重算，但不是驱动硬限矩，也不能证明有延迟、接触和量化时始终稳定。

增益范围按模式计算：共享参考要求 `0≤Kc≤250`、`2Dc+B≤1`；
旧 native 模式要求 `0≤Kc≤500`、`Dc+B≤1`，两者均继续核对每轴更小的配置边界。
两侧量程、方向和零偏分别处理；位置、速度、前馈字段或关节边界超出允许范围会明确拒绝或停止。
量化总力矩需求超过该轴 `TMAX` 时发布 `protocol_saturated_a/b` 提示；
它是需求超过协议量程的判断，不是设备实际饱和传感器，也不等于实际输出了该估算力矩。
`max_torque=0` 不关闭驱动保护，不承诺无限物理输出；`TMAX` 和前馈指令上限也不是总 PD 输出的硬限矩证明。

## 从共享标定启用摩擦补偿

硬件默认启用补偿，直接读取统一配置顶层 `system_parameters_file` 指向的
[config/system_parameters.yaml](../../config/system_parameters.yaml)，不用在双边面板重复输入模型参数。
每次显式开始都重新读取文件，分别核对两轴 namespace、hardware/simulation 环境、motor ID、
MIT 模式、方向、软件零偏与协议量程。已保存的合格模型或带人工接受记录的候选均由同一加载器验证。
开启补偿但任一模型缺失、身份不匹配或文件无效时，在使能前拒绝并显示原因；
可在失能时明确关闭补偿，使用纯 PD 双边耦合。运行中不读取文件，也不热替换模型。
待机时每秒更新模型预览，驱动完成初始化或标定保存新模型后，面板自动更新就绪状态；
首次开始前的相对位置显示“待建立启动基准”，停止后保留本次基准。

| 参数 | 配置范围 | 含义 |
| --- | ---: | --- |
| `friction_compensation_enabled` | `true` / `false` | 硬件默认开启；仿真 bringup 默认关闭，不能借用硬件模型 |
| `friction_compensation_fraction` | 0–1 | 摩擦模型补偿比例；0 表示零补偿，1 仍保留死区、滤波及输出上限 |
| `friction_torque_limit` | (0, 0.5] Nm | 每轴模型摩擦上限；正应用预算模式下还受总预算一半限制；不包含独立编码修正 |
| `max_torque` | ≥0 Nm | 0 关闭额外应用限矩；正值约束量化 PD＋前馈总估算 |

默认只补偿模型摩擦的 60%，为模型误差保留余量。100% 补偿在真实摩擦小于拟合值时可能
持续向系统供能，使松手后仍运动；低速死区和力矩斜率限制不能消除这种过补。
默认值不是任意负载或未知固件响应下的稳定性保证，增益与补偿应一起做轻推后释放验证。

补偿仅用各轴自身的反馈速度计算摩擦，零预算模式采用上述区间中点估计；保留 0.02 rad/s 死区、0.03 rad/s 平滑尺度、
10 ms 速度滤波和 5 Nm/s 力矩斜率。静止不主动起步，换向立即清空旧补偿；
不把标定中的惯量、偏置、重力或刚度当作摩擦前馈。前馈请求上限不超过正应用预算的一半，
实际解码后的前馈（包括 MIT 零码偏置）再参与共同增益预算；预算为 0 时仍保留独立模型摩擦上限，
模型摩擦与编码修正的总和受驱动前馈字段边界约束。
补偿不会消除转子、传动机构或负载惯量，模型残差、低速死区和采样延迟也仍然存在；
较小本地阻尼和更充分的摩擦补偿可以改善拖动手感，不能保证零惯量、零阻力或任意负载下无角差。

当前已保存的快速标定速度域约为电机1 -0.411…0.391 rad/s、电机2 -0.327…0.323 rad/s。
域外按相应端点限幅计算，面板会显示“速度超出标定范围”；这不是更高速度已经通过标定。
面板同时显示每轴模型、来源、速度范围、当前摩擦前馈及 PD＋前馈总估算。

另有默认关闭的显式速度助力参数 `extra_viscous_a`、`extra_viscous_b`（Nm·s/rad），
非零时必须同时指定 `extra_viscous_velocity_limit`（rad/s）。它们是控制器增益，
不修改标定文件，也不扩大原模型的已验证速度范围。原模型仍按自己的端点夹紧，
附加项按独立速度上限计算；两项共用10 ms速度滤波、零速/换向清零、5 Nm/s变化率和
`friction_torque_limit` 总上限。关闭补偿或将比例设为零时，附加项也完全关闭。
参数只能在双轴停止且新鲜失能时设置。
配置和面板API保留这些值，补偿状态说明其独立来源；普通默认仍为零，显式[三轴物理profile](../../config/bilateral_physical_rig.md)使用A=0、B=0.02584737521699079、速度上限13.2和共享补偿上限0.4 Nm。
系数来源、仿真及B100短轮/释放/连续长测证据见[三电机阶段报告](../../docs/experiment-history.md#three-motor-bilateral-baseline-2026-11-05)。
本台架通过不替代其他电机、负载或拆除C后的实物验证；A/C摩擦仍不能从组合辨识中唯一拆分。
驱动若启用正值估算力矩停机门限，而应用预算为 0 或大于该门限，会在使能前明确拒绝；
控制器不自动修改或关闭已有驱动保护。

## 配对、降级与停机

- 健康门禁的反馈配对按真实单调采集时间选择较旧成员尽可能新的合格历史组合。
  该pair只使用双方未消费的新样本，不插值、不篡改时间戳；控制器与采集节点应在同一主机时钟域。
  同轴递增序号但相同采集时间的反馈合并为最新值，不重复消费已配对的时间点；时间倒退或序号重放仍拒绝。
- native 等待配对期间保留上一组合及速度滤波结果，按采集时间作上述有限预测；
  共享参考使用两轴最新位置及各自按采集时间推进的速度滤波，不做位置预测。
  差模弹簧另按[共同时间历史](#common-time-candidate)取得位置，不消费或改写健康pair；速度阻尼仍用原路径。
  每周期用本轴最新反馈重算输出估算，正预算模式才据此缩小增益。
- 有效配对超过 `feedback_age` 时双方 Kp/Kd=0、前馈请求0，并清空对侧速度滤波及摩擦滤波/斜率状态；不是抱闸。
- 三组新鲜配对后按 `recovery_time` 渐进恢复；再次失联重新清零恢复进度。
- 任一轴或有效配对超过 `feedback_stop`、设备/主机故障、协议/坐标变化、控制器停顿、
  命令拒绝、其他合法控制源覆盖目标或浏览器心跳失联时请求双侧失能；不会自动重新使能。
- 明确 STOP 后不因新数据到来恢复旧目标。第一次停止原因保留到此次停止结束。

控制源覆盖通过驱动状态快照检测；短于状态发布间隔的瞬时覆盖不保证被观察到，
因此仍应只运行一个运动应用，不能把这个检查视为独占控制锁。

配置位于 [统一配置](../../config/dm_motors.yaml) 的对应 package/launch。
控制器和驱动频率由所选 profile 定义；健康pair年龄/时差为20 ms / 5 ms，差模位置插值跨度另按上述8 ms候选边界检查，
失联停止 80 ms、恢复爬升 100 ms，沿用生产驱动 200 ms watchdog。
这些是 ROS 进程链路的配置，不声称等同 ref 串口线程的时延。
单独附加时会核对驱动的控制率、命令有效期、watchdog 和状态频率，不兼容则拒绝使能。
两台驱动的 `control_rate` 均须不低于双边 `rate`；当前默认 500 Hz 控制器不能直接使用旧 200 Hz 驱动。

正应用预算同时包含 PD 与摩擦前馈，不是反馈力矩超过该值就停机的门限，也不是虚拟外力上限。
关闭该预算时，反馈、通信和驱动保护链路继续生效。
两种模式的附加运动限制均默认关闭，保留显式启用行程、反馈力矩等额外约束的能力。
双边 bringup 中电机驱动的 `estimated_torque_limit` 和 `measured_torque_limit` 默认设为 0（关闭），
避免再叠加固定 1 Nm 门限，导致正常双边耦合被另一个不一致的预算打断。
标准 bilateral profile 的真机驱动仍启用主机保护并保留 55°C MOS/转子温度停机；
没有关闭设备故障、协议范围或通信看门狗。2026-10-30 本次部署复用的现场驱动另保留其原有
50°C MOS/转子温度和 26 rad/s 实测速度保护，并未自动改成 profile 的其它保护值。
独立附加控制器不会修改已有驱动的保护配置，显式配置的机械关节边界及驱动门限仍然生效。
任何模式都保留数据有效性、通信、设备故障和显式停机检查；不设置两侧角差停机阈值。

### 驱动力矩门限与重启

2026-10-22 的现场故障中，双边控制器已设置 `motion_limits_enabled=false`、`max_torque=10`，
但两台驱动仍启用了旧 bringup 配置的 `estimated_torque_limit=1`、`measured_torque_limit=1`。
因此驱动以 `estimated combined MIT torque exceeds configured limit` 锁存主机故障；
两台反馈的 `device_fault=false`、`status=0`，不是电机固件故障。

双边场景现已移除这两个默认的固定门限；驱动仍保留温度保护。
双边控制器也会直接报告驱动给出的具体错误，而不是仅显示“需要正常的 MIT 反馈”。
显式设置的驱动门限仍然会生效，关闭应用的附加运动限制不会悄悄绕过它们。

这些驱动参数只在启动时读取，不能用 `ros2 param set` 热更新。
更新并构建后，应先在原启动终端退出旧 bringup，再重新启动整套双边 bringup；
只刷新网页、重新启动 dashboard 或反复清除主机故障，不能解除旧进程中的 1 Nm 门限。
应使用 `ros2 launch dm_motor_bringup bilateral_control.launch.py` 选择 bilateral profile，
该 profile 显式配置驱动门限；单独附加控制器不会把已有驱动转换成该 profile。
旧驱动若仍为 200 Hz，也须在停止后按 500 Hz 双边配置重启；只处理 1 Nm 门限仍无法通过频率核验。
若保留旧驱动的正值估算保护，应选择不超过该门限及驱动指令边界的正应用预算；
`max_torque=0` 与旧的 1 Nm 估算门限不兼容，会在开始核验时拒绝，而不会自动关闭保护。
重新启动仍保持失能，须检查参数后显式开始。2026-10-22 修复时的默认 PD 预算为 0.5 Nm；
现场曾设置的 10 Nm 不属于当时已经验证的 0.5 Nm 测试条件。

回归在隔离的虚拟 CAN 上复现了相同的驱动报错。修正后，等价硬件保护配置下的
PD 估算/实测力矩超过 1.2 Nm、位移超过 0.35 rad 时不会因旧门限误停；
显式附加保护、设备故障、通信失联和无效反馈仍经过测试。修复过程没有重新使能现场电机。

## ROS 接口

- `bilateral_control/state`：`dm_motor_interfaces/msg/BilateralState`，包括阶段、两轴原点、
  相对误差、配对年龄/时差、降级/恢复、共同增益及最近实际请求目标。
  `application_torque_limited` 表示正应用预算已开启，不表示本周期已经发生增益缩放；
  `protocol_saturated_a/b` 表示估算需求超出协议力矩量程；
  `driver_configuration_known_a/b` 区分已读取驱动配置与默认空结构。
  `control_mode` 与 `required_velocity_bandwidth` 标识本进程的只读启动配置；
  `velocity_bandwidth_verified` 及 `motor_a_velocity_bandwidth` / `motor_b_velocity_bandwidth`
  记录本次 START 独立核验的结果，STOP 后清除；0 读回表示未知，不能解释为已核验的实际零带宽。
  `friction_torque_a/b` 为原模型与显式附加速度助力的合计，`quantization_torque_a/b` 为编码修正，
  `target_a/b.torque` 为两者合计的前馈请求；它们都不是设备实际输出力矩测量。
- `bilateral_control/start` / `stop`：`std_srvs/srv/Trigger`，接受请求不等于已经完成。
- `bilateral_control/operator_control`：`dm_motor_interfaces/srv/BilateralControl`，
  网页使用有心跳的显式会话；START/HEARTBEAT 须带新鲜 ROS 时间戳和 `(0,0.5]` 秒有效期，
  过期请求拒绝，STOP 不因过期而拒绝。程序可使用 start/stop 服务。
- 动态参数只在停止且两台新鲜失能时修改；电机命名空间、控制模式、要求速度带宽、控制率和生命周期时序为启动参数。

面板可在双侧新鲜失能时单独“应用设置”，不使能；配对条件不满足时仍可修正参数。
网页 START 另外要求命令 Topic 已发现且存在新鲜失能配对。
配置区显示有效耦合 Kc/Dc；主要状态区展示量化后的原生 MIT Kp/Kd、已应用预算，
以及预算缩放和通信恢复各自的比例，并只读显示速度带宽核验状态。
每轴分别显示未缩放需求、量化总估算、实际反馈与协议需求提示；驱动保护未读取时显示“未读取”，
不会把消息结构中的默认 0 解释为保护已经关闭。读取后区分“未设阈值”和“保护未启用”。
HTTP STOP 会撤销旧网页会话，等待本次 STOP 请求之后发布的双侧失能确认；
无法确认时返回错误，不用旧缓存中的“已停止”冒充完成。控制页不可见或退出会释放会话，
请将双边面板与单机外力面板并排显示，不要通过隐藏控制页来操作另一端。

## 短时人工轻推与往返拖动

`manual_test` 复用自动检测的回零、启动核验、独立守卫和双停流程，不发送力矩脉冲或虚拟角差。
现场操作者准备好后，可运行：

```bash
ros2 run dm_motor_bilateral_control manual_test --hardware --axis a --scenario touch
```

`--axis b` 指定另一轴；`--scenario drag` 检查往返运动。每次固定为：物理回零 → 双边启动 →
双手离开静置 5 秒 → 按提示轻推或缓慢往返 5 秒 → 松手提示后观察 5 秒 → 双轴停机。
每阶段都有即时提示，人工窗口内无需输入文字；当前各轴相对行程限制为 ±0.08 rad，
速度、实测力矩和温度停止门槛为 0.8 rad/s、0.7 Nm、45°C。要求控制率 500 Hz、实际带宽 100 Hz，
并保留原反馈与父进程失联双停。每次记录独立目录、逐帧数据、原始图和配置。

两轴均须产生超过编码分辨率和本次基线噪声的有效运动；往返场景还须有双向行程。
人工段的主动往返与振动分别检查；接触阶段也检查持续可分辨窄带纹波。
后 5 秒若存在持续可分辨纹波、反复逆转、
未停稳或同步误差未收敛，即使最后一小段安静也不能通过。
没有触碰或只有一轴有效运动时结果为 `inconclusive`，不能由人工声明升级为通过。

自动记录合格时仅为 `pending_operator_confirmation`：程序没有外力传感器，
松手提示不能证明实际已经松手。停机后，操作者须如实声明是否完成操作、是否按提示松手、
观察阶段是否没有再次触碰、是否感到振动、拖动阻力是否可接受，并填写主观感受：


角差检测由 `--angle-offset-deg` 选择，要求非零且绝对值不超过 30°。流程是：

1. 使用独立操作会话启动双边控制，等待正常反馈和完整恢复，无扰动观察 5 秒。
   独立守卫检查这 5 秒的逐帧数据：每轴速度 RMS 不超过 0.04 rad/s、位置范围不超过 0.002 rad，
   且采集覆盖完整；基线存在运动或振动时立即结束，不继续注入角差。
2. 通过同一会话的 `<controller>/angle_offset` 服务加入虚拟相对角差。
   `--transition-time` 使用五次曲线从 0 平滑过渡到请求值，真机允许 2–5 秒，默认 2 秒；
   仿真允许 0–5 秒以便检验阶跃响应。有效 Kc=50 时直接注入 30° 会产生每侧约 26.2 Nm 的初始 PD 需求，
   因此真机接口不接受直接阶跃。过渡不会改动反馈、启动原点或软件零偏。
3. 确认本次事件的已施加偏置达到目标后，**保持偏置再观察 5 秒**，随后双轴停止。
   `--observe-seconds` 在角差模式下可设为 5–9 秒。偏置不会在 ACTIVE 中先撤销再继续控制；
   正常结束、超时、反馈降级或会话丢失均先停止输出，再清除偏置。

偏置 `o` 的定义是 `virtual_position_error = position_error + o`，其中原有
`position_error = (qA-originA) - direction*(qB-originB)` 表示健康历史pair中的相对位置误差；
它不是当前差模共同时间弹簧误差的直接观测，角差偏置本身的符号与到期停止语义保持不变。
在 `native` 模式，正偏置使 A 的目标减去 `o`、B 的目标加上 `direction*o`；
在 `shared_reference` 模式，两侧目标分别改变 `-o/2` 和 `direction*o/2`。
两种模式下，+30° 注入后的稳态目标都是
真实相对角差约 -30°、虚拟误差约 0。两轴的运动分配由惯量、摩擦及负载决定，不要求各自转动 15°。
报告分别记录原始角差、虚拟误差和施加量；虚拟误差最终须在 0.01 rad 内，不能只凭偏置服务应答判定通过。

原有单轴力矩短脉冲检测仍可显式使用；不传 `--angle-offset-deg` 时选择该模式：

```bash
ros2 run dm_motor_bilateral_control auto_test --hardware --axis a --torque 0.2 --pulse-duration 0.1 --observe-seconds 5
```

回零并启动双边控制后，通过同一操作会话的 `<controller>/disturbance` 显式请求一次单轴前馈扰动。
`--axis a|b` 选择轴，`--torque` 选择方向和幅值，要求 `0 < |torque| <= 0.3 Nm`；
`--pulse-duration` 为 0.04–0.2 秒，默认 0.1 秒。确认对应事件结束、两侧扰动力矩均归零后，
继续双边控制观察 5 秒，`--observe-seconds` 可设为 5–10 秒，再双轴停机。
力矩脉冲与角差注入互斥；所有注入都要求当前 START 会话和新鲜心跳。

检测沿用当前双边增益、力矩预算与摩擦补偿配置。运行期间临时开启附加运动限制，
结束并确认失能后恢复原设置；恢复失败会记为失败。独立守卫进程订阅逐帧反馈，
检查速度超过 0.8 rad/s、实测力矩超过 0.7 Nm、温度达到 45°C、反馈失鲜超过 50 ms、
控制源变化和故障。回零行程限制在起点到 0 的区间外各留 0.08 rad；
双边阶段记录一次基准并保持不变：无扰动基线和短脉冲模式每轴最多偏离 0.08 rad，
角差过渡与保持阶段允许每轴偏离 `abs(offset_radians)+0.08` rad，兼顾运动主要由单轴承担的情况。
父进程失联超过 250 ms 或退出、
总时限或 ACTIVE 时限到达时，守卫直接向两轴发送 DISABLE 并请求控制器 STOP，
持续重发直到收到停机之后的新鲜失能反馈；父进程也有独立的停机路径。
这些是**实测值触发停机的实验边界，不是 MIT 总输出力矩的硬夹紧**；
MOVE 的前馈 0 和扰动的 0.3 Nm 上限也不限制 PD 力矩。

每次检测新建独立目录，默认位于 `~/.ros/dm_motor_bilateral_control/auto-tests/`，
也可通过 `--output /绝对路径/空目录` 指定；已有实验不会被覆盖。
`report.md`、`report.json` 记录参数、归零结果、扰动事件、观察指标和停机确认，
`motion.svg` 显示运动曲线；`feedback.csv` 逐帧保留两轴的位置、速度、实测力矩、采集时间和序号，
`state.jsonl` 保留驱动/控制器状态与阶段事件，`monitor.json` 保存独立守卫最终结果。
停机尚未确认时守卫继续运行，最终 `monitor.json` 尚不会生成，不能据此认定已停机。

- `passed`：流程、原始数据覆盖和新鲜停机确认均通过，有可辨识的注入响应，且两轴最后 1 秒
  的速度 RMS 不超过 0.04 rad/s、位置范围不超过 0.001 rad。角差模式还要求无扰动基线通过、
  指定偏置保持完整且真实运动闭合虚拟角差。还检查整个过渡及保持段：每轴须沿正确方向运动
  至少请求角度的 10%（且不少于两格编码器分辨率），没有连续可分辨的周期纹波或反复逆向。
  报告区分首次到达和持续达到 90%/95% 闭合，以及经窗口确认的停稳时间；不能只以尾段安静通过。
  进程退出码为 0。
- `failed`：保护触发、流程或记录不完整、尾段未停稳、停机或设置恢复未确认等。退出码为 2。
- `inconclusive`：仅用于短脉冲流程完成但未产生可区分于编码器量化的运动，无法验证释放后的响应。
  当前判定要求至少一轴的扰动及观察段位移范围达到两个位置量化步长（默认量程约 0.00076 rad）；
  退出码为 2。角差模式中没有可辨识响应或未闭合目标角差均为 `failed`，基线静止则是预期行为。

这些检测分别检查保持角差时的响应或短脉冲撤除后的响应，不替代人工拖动或不同接触、负载验收。

### 2026-10-22 抖动排查与阻尼默认值

读取现场时双方已经失能。保留的运行配置为 `Kc=8, Dc=0.5, B=0, max_torque=10`，
并非上述通过验收的参数。最后一组请求的 PD 估算约为 -9.91 / +9.90 Nm，
速度目标约为 -10.24 / +7.41 rad/s；这些是停止前的请求记录，不是读取时仍在输出。
目标 Topic 仅发现双边控制器一个发布者，没有发现另一套持续争抢目标的控制器。
驱动的固定估算/反馈力矩门限均已为 0，当前反馈约 500 Hz、控制器记录的降级次数为 0。

日志明确记录电机 2 因 `position outside motor joint bounds` 停止，实际关节/协议范围为
[-12.5, 12.5] rad。读取时两侧位置约 -10.95 / -11.07 rad，电机 2 保留主机保护故障。
不能再通过取消这一范围保护继续运行；它是停止原因，不是抖动稳定性问题的修复办法。
也不能从停机后的单个快照精确还原振荡频率或证明唯一的物理根因。

已确认的运行风险是缺少本地阻尼并使用了已测预算 20 倍的力矩预算。
在理想对称模型的共同运动中，`B=0` 没有本地耗能项；`B>0` 引入
`-B*(vA²+vB²)` 的耗能，但不增加共同位置保持。这不能替代包含时延、量化和机械负载的稳定性验证。
在 2026-10-22 这次排查中，当时的默认值统一为实机验证过的 `Kc=16, Dc=B=0.35, max_torque=0.5`；
未重新引入固定 1 Nm 或附加行程停机门限，也不禁止专家显式配置其他参数。

现场仅在确认双侧失能后原子更新了这四个应用参数，没有发送使能、回零或故障复位请求。
电机 2 的故障锁存仍保留。恢复输出前应检查机械位置和剩余工作区间，刷新页面确认参数，
再按现场流程处理故障；不要直接恢复到 10 Nm 复现剧烈振动。

驱动的反馈保护错误现会包含具体的越界位置、速度、力矩或温度及阈值，
不再仅给出笼统的 `measured feedback protection exceeded`。
同时修正了保护触发后同一控制周期可能沿用旧状态继续提交保持目标的问题；
保护阈值和连续异常样本判定没有放宽。
默认共同运动耗能、共同位置不被锁定、显式位置保护及驱动/双边集成回归共 81 项通过，
所有新增运动验证仅在隔离虚拟 CAN 上执行；没有在现场重新使能来复现 10 Nm 抖动。
